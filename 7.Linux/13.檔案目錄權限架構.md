# 檔案權限

每個檔案（目錄）可依不同身分給予相對應的權限。

## 三種身分

| 身分 | 縮寫 | 說明 |
|------|------|------|
| 檔案擁有者 | `u`（user） | 建立或擁有該檔案的帳號 |
| 群組成員 | `g`（group） | 與擁有者同群組的帳號 |
| 其他人 | `o`（others） | 不屬於以上兩類的所有帳號 |

> ==群組權限的判斷是依據帳號的**主要群組**==

## 三種權限

| 權限  | 縮寫  | 數值  | 對檔案的意義                        | 對目錄的意義                                                |
| --- | --- | --- | ----------------------------- | ----------------------------------------------------- |
| 讀取  | `r` | `4` | 檢視檔案內文（`cat`、`less`、==cp== 等） | 檢視目錄的內容物（`ls`）                                        |
| 寫入  | `w` | `2` | 修改並存檔（`vim`、`nano` 等）         | 異動目錄的內容物（新增/修改/刪除檔案及子目錄）（`touch`、`mkdir`、`rm`、`mv` 等） |
| 執行  | `x` | `1` | 將檔案當成程式執行（`./file1`）          | 允許進入到該目錄內（`cd`）                                       |


## 判斷權限原則

1. 判斷你的**身份**（擁有者 / 群組成員 / 其他人）
2. 依據你的身份判斷**能做什麼**

> ==可否新增/刪除目錄內的檔案，看的是**該目錄的 `w` 權限**，且需同時具備 `w` 及 `x`==

# ls -l 檢視檔案資訊

每個檔案（或目錄）都有**權限位元**，於建立時由系統給予預設值，擁有者可進行修改。

```
-rwxr-xr-- 1 user1 group1 4096 Aug 9 10:00 file1.sh
^─────────
│ │││ │││ │││
│ ││└─┘│└─┘└─── others 權限（r--）
│ ││   └──────── group 權限（r-x）
│ └┘            
│  └──────────── user 權限（rwx）
└─────────────── 檔案類型
```

## 第 1 個位元：檔案類型

| 符號 | 說明 |
|------|------|
| `-` | 一般檔案 |
| `d` | 目錄 |
| `l` | Soft link（軟式連結） |

## 後 9 個位元：權限位元

每 3 個為一組，分別對應 **user / group / others**：

| 符號 | 權限 |
|------|------|
| `r` | read（讀取） |
| `w` | write（寫入） |
| `x` | execute（執行） |
| `-` | 無此權限 |

## 讀懂 ls -l 的範例輸出

```bash
$ ls -l /etc/passwd
-rw-r--r-- 1 root root 2345 Aug 9 10:00 /etc/passwd
```

| 欄位 | 值 | 說明 |
|------|----|------|
| 類型+權限 | `-rw-r--r--` | 一般檔案；擁有者 rw-、群組 r--、其他人 r-- |
| 硬式連結數 | `1` | |
| 擁有者 | `root` | |
| 群組 | `root` | |
| 大小 | `2345` | 位元組 |
| 時間 | `Aug 9 10:00` | 最後修改時間 |
| 檔名 | `/etc/passwd` | |

# 數值表示法

權限也可以用三位數字表示（`r=4`、`w=2`、`x=1`，相加得到每組的值）：

| 數值 | 二進位 | 權限組合 |
|------|--------|---------|
| `7` | `111` | `rwx` |
| `6` | `110` | `rw-` |
| `5` | `101` | `r-x` |
| `4` | `100` | `r--` |
| `0` | `000` | `---` |

**常見組合範例：**

| 數值 | 字元表示 | 常見用途 |
|------|---------|---------|
| `755` | `rwxr-xr-x` | 一般可執行檔、目錄 |
| `644` | `rw-r--r--` | 一般文字檔 |
| `700` | `rwx------` | 私人可執行檔 |
| `600` | `rw-------` | 私人文字檔（如 SSH 金鑰） |
| `777` | `rwxrwxrwx` | 所有人都可讀寫執行（不建議） |

# 修改權限（chmod）

```bash
chmod [選項] 模式 檔案或目錄
```

## 數值模式

```bash
chmod 755 file1.sh         # 設定為 rwxr-xr-x
chmod 644 file1.txt        # 設定為 rw-r--r--
chmod -R 755 dir1/         # 遞迴設定 dir1 及其所有內容
```

## 符號模式

語法：`[ugoa][+-=][rwx]`

| 符號 | 說明 |
|------|------|
| `u` | user（擁有者） |
| `g` | group（群組） |
| `o` | others（其他人） |
| `a` | all（所有人，等同 `ugo`） |
| `+` | 新增權限 |
| `-` | 移除權限 |
| `=` | 設定為指定權限（覆蓋） |

**範例：**

```bash
chmod u+x file1.sh         # 擁有者新增執行權限
chmod go-w file1.txt       # 群組與其他人移除寫入權限
chmod a+r file1.txt        # 所有人新增讀取權限
chmod u=rwx,go=r file1.sh  # 擁有者 rwx，群組與其他人 r--
```

# 修改擁有者（chown）與群組（chgrp）

> **使用時機**：檔案複製給其他人使用時，若擁有者未改成對方，可能造成操作權限不足

## chown

```bash
chown [-R] 帳號 檔案/目錄
chown [-R] 帳號:群組 檔案/目錄   # 同時修改擁有者與群組
```

- 將檔案或目錄的擁有者修改
- `-R`：子目錄內的檔案也一併修改
- 需 root 權限

```bash
sudo chown user1 file1              # 將擁有者改為 user1
sudo chown user1:group2 file1       # 擁有者改為 user1，群組改為 group2
sudo chown -R user1 dir1/           # 遞迴修改 dir1 及其所有內容
```

## chgrp

```bash
chgrp [-R] 新群組名稱 檔案/目錄
```

- 將檔案或目錄所屬群組改為新群組
- 群組名稱必須是已存在系統中的
- 需 root 權限；`-R`：子目錄內的檔案也一併修改

```bash
sudo chgrp group2 file1   # 將 file1 所屬群組改為 group2
sudo chgrp group2 dir1    # 將 dir1 所屬群組改為 group2
```

> **練習**：請用 root `touch` 一個檔案，並把該檔案設定成「只有」user1 才看得到

# 綜合範例

```bash
# 建立腳本並給予適當權限
touch myscript.sh
chmod 755 myscript.sh   # rwxr-xr-x：擁有者可執行，其他人只能讀與執行

# 設定敏感設定檔，只有擁有者能讀寫
chmod 600 ~/.ssh/id_rsa

# 讓群組成員也能寫入某目錄
chmod g+w /home/share/

# 查看目錄本身的權限（加 -d，不列出內容）
ls -ld /home/user1/
```

# 特殊權限

## SUID（Set UID）

- 限適用於**執行檔**（binary program）
- 使用者對該檔案必須具有 `x` 的權限
- 只有在**執行過程中**，使用者可暫時取得**擁有者（owner）的權限**

**範例：`/usr/bin/passwd`**

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root ... /usr/bin/passwd
#      ^ s 表示有 SUID，執行時暫時取得 root 權限
```

- `passwd` 的擁有者是 root，一般使用者執行時會**暫時取得 root 權利**，以便修改 `/etc/shadow`
- 權限位元中，擁有者的 `x` 位置顯示為 `s`（大寫 `S` 表示無 x 權限但有 SUID）

## SBIT（Sticky Bit）

- 通常設定在**目錄**上
- 目錄對所有人開放寫入（`w`）時，任何人都能刪除他人的檔案
- 加上 Sticky bit 後，**只有自己與 root** 有權利刪除該目錄內自己建立的檔案或目錄

**範例：`/tmp`**

```bash
ls -ld /tmp
# drwxrwxrwt 1 root root ... /tmp
#          ^ t 表示有 Sticky bit
```

- `/tmp` 是所有帳號均可寫入的暫存目錄
- 若只設 `777` 而沒有 Sticky bit，你放的資料可能被其他人刪掉
- 加上 SBIT 後，user1 無法刪除 user2 在 `/tmp` 下建立的檔案
