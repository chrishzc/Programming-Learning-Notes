# Linux 上的軟體——套件（Packages）

依 Linux 核心而設計的軟體稱為套件，通常包含：
- 可執行程式碼（執行檔及函式庫）
- 其他額外資訊（套件版本、相依性、說明文件）

## 安裝套件的三種方式

| 方式               | 優點                      | 缺點                   |
| ---------------- | ----------------------- | -------------------- |
| **線上安裝**         | 簡單方便                    | ==必須連線至伺服器；版本選擇不自由== |
| **執行安裝檔**        | 從網路或光碟取得安裝檔，再透過套件管理程式安裝 | —                    |
| **自行編譯 TarBall** | 版本選擇自由；可修改程式碼；可移植至其他平台  | 難度較高                 |

# 管理機制：DPKG 與 RPM

|            | DPKG            | RPM                             |
| ---------- | --------------- | ------------------------------- |
| **適用發行版**  | Debian / Ubuntu | RedHat / Fedora / CentOS / SuSE |
| **安裝檔格式**  | `*.deb`         | `*.rpm`                         |
| **線上管理機制** | APT             | YUM                             |
| **使用指令**   | `dpkg`、`apt`    | `rpm`、`yum`                     |

# DPKG 系統（Ubuntu 適用）

- ==安裝檔下載後暫存於 `/var/cache/apt/archives/`==
- 可自動處理套件的**依賴關係**

## apt（高階工具）

DPKG 系統的中階套件管理工具，可進行線上安裝。

| 類型     | 指令                            | 說明                 |
| ------ | ----------------------------- | ------------------ |
| **安裝** | `apt install 套件名`             | ==安裝套件==           |
|        | `apt install -y 套件名`          | 詢問是否安裝時直接回答 Yes    |
|        | `apt install --reinstall 套件名` | 重新安裝套件             |
|        | `apt download 套件名`            | 只下載安裝檔（不安裝）        |
| **移除** | `apt remove 套件名`              | 移除套件，但**保留**設定檔    |
|        | `apt remove --purge 套件名`      | 完整移除套件，**不保留**設定檔  |
|        | `apt autoclean`               | 移除無用套裝軟體檔案，但保留安裝檔  |
|        | `apt clean`                   | 移除無用套裝軟體檔案，不保留安裝檔  |
| **更新** | `apt update`                  | ==更新套件清單==         |
|        | `apt upgrade`                 | ==逐一升級所有有新版的軟體套件== |
| **查詢** | `apt search 字串`               | 搜尋可用套件             |
|        | `apt show vim`                | 查詢 vim 套件資訊        |

**範例：**

```bash
sudo apt install subversion   # 安裝 subversion
apt show subversion           # 檢視版本資訊
svn --help                    # 執行 subversion 的指令
apt download git              # 只下載 git 的 deb 檔
```

## dpkg（低階工具）

屬於 DPKG 系統的低階套件管理工具，安裝檔格式為 `*.deb`。

| 類型 | 指令 | 說明 |
|------|------|------|
| **安裝** | `dpkg -i XXX.deb` | 需自行下載安裝檔 |
| **查詢** | `dpkg --info XXX.deb` | 查詢安裝檔資訊 |
| | `dpkg --list` | 顯示目前已安裝的套件清單 |
| **移除** | `dpkg -r vim` | 移除 vim（套件的名稱） |

**範例：手動下載並安裝 git（含依賴套件）**

```bash
# 下載並安裝依賴套件
apt download git-man liberror-perl
sudo dpkg -i git-man_xxx.deb
sudo dpkg -i liberror-perl_xxx.deb

# 下載並安裝 git
apt download git
sudo dpkg -i git_xxx.deb

# 測試是否安裝成功
git --help
```

# RPM 系統（RedHat / CentOS 適用）

## yum

| 類別     | 指令                     | 說明                |
| ------ | ---------------------- | ----------------- |
| **安裝** | `yum install 套件名`      | ==安裝套件==          |
|        | `yum -y install 套件名`   | 安裝時預設回答 yes       |
|        | `yum reinstall 套件名`    | 重新安裝套件            |
|        | `yumdownloader 套件名`    | 只下載安裝檔            |
| **移除** | `yum remove 套件名`       | 移除該套件             |
|        | `yum clean`            | 清除安裝時下載的暫時檔案      |
| **更新** | `yum update`           | 更新所有套件清單          |
|        | `yum upgrade 套件名`      | 更新該套件             |
| **查詢** | `yum list`             | 列出所有套件            |
|        | `yum list installed`   | 列出所有已安裝的套件        |
|        | `yum list update`      | 列出所有可更新的套件        |
|        | `yum search "KEYWORD"` | 搜尋與 KEYWORD 有關的套件 |
|        | `yum info 套件名`         | 以套件名查詢相關資訊        |

## rpm

> 套件異動需使用 root 權限

| 類別 | 選項 | 全名 | 說明 |
|------|------|------|------|
| **安裝** | `rpm -i XXX.rpm` | install | 以 rpm 安裝檔安裝套件 |
| **移除** | `rpm -e 套件名` | erase | 移除（解除安裝）該套件 |
| **更新** | `rpm -U XXX.rpm` | upgrade | 更新套件；若未曾安裝過也會執行安裝 |
| **查詢** | `rpm -q 套件名` | query | 查詢套件是否已安裝 |
| | `rpm -qa` | query all | 查詢目前系統上所有已安裝的套件 |
| | `rpm -ql 套件名` | query list | 查詢套件的內容清單 |

# 手動建置（TarBall）

Linux 真正可執行的檔案是**二進位檔案**（binary file），例如 `cp`、`ls` 等。  
寫完 C 程式後需要 C 編譯器，`gcc` 可將 C 原始碼轉換成機器可以執行的程式碼。

## 什麼是 TarBall？

TarBall 就是以 `*.tar.gz` 等形式壓縮的套件原始檔，通常包含：
- 原始碼（如 `*.c`、`*.h` 等）
- 組態設定檔（`configure`）：偵測當前建置環境的資訊，並檢查相關工具是否存在（如 gcc）
- 建置說明（如 `INSTALL`、`README`）

## 編譯安裝流程

```bash
# 解開 TarBall 後，進入目錄依序執行：
./configure       # 組態設定，執行成功後會產生 Makefile
make              # 依照 Makefile 進行編譯、連結，於當前目錄建置出執行檔
sudo make install # 將成果安裝至系統目錄，讓系統方便使用
```

預設安裝位置包括：`/usr/local/bin`、`/usr/bin`、`/usr/local`

## 範例：編譯安裝 joe 編輯器

```bash
# 搜尋並下載 joe-4.4.tar.gz
tar -zxvf joe-4.4.tar.gz        # 解開 tarball
cd joe-4.4/
./configure                      # 組態設定
# 若遇到 gcc 未安裝錯誤：
sudo apt install gcc
./configure                      # 重新執行
make                             # 建置
sudo make install                # 安裝至系統目錄
joe                              # 執行（按 Ctrl+K 後再按 q 結束）
```

# 指定安裝路徑

建議在執行組態設定時指定路徑：

```bash
./configure --help                   # 查詢支援的選項
./configure --prefix="自訂的安裝路徑"

# 範例：安裝到 /tmp/bin
./configure --prefix=/tmp/bin
make
make install

# 修改 $PATH 以方便系統尋找執行檔
PATH=$PATH:/tmp/bin/
```

# 清除編譯成果

於 `Makefile` 所在目錄執行（擇一即可）：

> 必須依賴 Makefile 內所撰寫的規則，才能執行相應動作

| 指令 | 說明 |
|------|------|
| `make clean` | 移除新建置的檔案 |
| `make mrproper` | 移除新建檔案 + 移除設定檔 |
| `make distclean` | 移除新建檔案 + 移除設定檔 + 移除暫存檔、修補檔案等 |
