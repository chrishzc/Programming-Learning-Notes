#### 9.1 傳統 VPN 概念回顧

**VPN（Virtual Private Network，虛擬私人網路）** 透過加密隧道，讓遠端裝置彷彿身處於私有網路內部。

| 特性 | 說明 |
|------|------|
| 核心目的 | 保護傳輸中的流量、隱藏真實 IP、存取內網資源 |
| 傳統協定 | OpenVPN、IPSec、L2TP |
| 常見問題 | 集中式架構、效能低、設定複雜、Hub-and-Spoke 瓶頸 |

> 待補充：傳統 VPN 在 DevSecOps 場景中的局限（全網路存取 vs 最小特權存取）

---

#### 9.2 WireGuard — 現代輕量 VPN 協定

**WireGuard** 是一個現代化、高效能的 VPN 協定，已於 Linux 5.6 起納入核心。

| 面向 | WireGuard | OpenVPN |
|------|----------|---------|
| 程式碼量 | ~4,000 行 | ~70,000 行（攻擊面更大）|
| 效能 | 待補充（核心層執行，延遲極低）| 待補充 |
| 加密演算法 | ChaCha20、Poly1305、Curve25519 | 可配置（複雜度高）|
| 設定複雜度 | 待補充（介面簡潔）| 待補充 |
| 狀態 | 無狀態（Stateless）| 有狀態 |

**核心運作原理**：

> 待補充
>
> 提示：Public/Private Key Pair → Peer 配置 → Kernel-level 加密隧道


#### 9.3 Tailscale — 零信任 Mesh VPN

**Tailscale** 是以 WireGuard 為底層協定構建的**零信任 Mesh VPN** 服務，核心概念是「每個節點直接與其他節點建立 P2P 加密連線」，無需集中式 VPN 伺服器作為流量中繼。

**架構對比**：

| 架構 | 傳統 VPN（Hub-and-Spoke）| Tailscale（Mesh）|
|------|------------------------|----------------|
| 流量路徑 | 所有流量 → 集中 VPN Server → 目的地 | 節點 A ↔ 節點 B 直連（P2P）|
| 單點故障 | 高（VPN Server 掛掉全斷）| 低 |
| 延遲 | 較高（繞道）| 待補充（直連更低）|
| 管理複雜度 | 待補充 | 待補充（幾乎零配置）|

**Tailscale 核心元件**：

| 元件 | 角色 |
|------|------|
| Control Plane（Tailscale 雲端）| 負責身份驗證與金鑰協商，**不處理實際流量** |
| DERP 中繼伺服器 | 當 P2P 直連失敗（NAT 穿透失敗）時作為備援中繼 |
| `tailscaled` daemon | 各節點本機執行的代理程式 |

**ACL 存取控制（零信任核心）**：

> 待補充
>
> 提示：Tailscale 的 ACL Policy 以 JSON/HuJSON 定義，可精確控制「哪個使用者/裝置可存取哪個服務的哪個 Port」，而非傳統 VPN 的「進來就全通」

```json
// Tailscale ACL Policy 骨架（待補充詳細說明）
{
  "acls": [
    {
      "action": "accept",
      "src": ["group:developers"],
      "dst": ["tag:k8s-cluster:6443"]  // 僅允許存取 K8s API Server
    }
  ]
}
```

**Tailscale 在 DevSecOps 的典型應用場景**：

- [ ] 遠端安全存取私有 K8s 叢集（取代跳板機）
- [ ] CI/CD Runner 安全存取私有 Registry 或 DB
- [ ] 多雲環境節點間的加密互連
- [ ] 開發者直接存取測試環境服務，無需暴露公網端口

---

#### 9.4 三者定位比較

| | VPN（通用概念）| WireGuard | Tailscale |
|--|--------------|----------|-----------|
| 層次 | 概念/技術類別 | 協定實作 | 基於 WireGuard 的完整平台 |
| 管理方式 | 依實作而定 | 手動設定 | 控制平面自動化 |
| 適合場景 | 待補充 | 待補充（自架、高度自定義）| 待補充（快速部署、團隊協作）|
| 零信任支援 | 傳統架構較弱 | 協定層支援 | 原生支援（ACL + 身份驗證）|
