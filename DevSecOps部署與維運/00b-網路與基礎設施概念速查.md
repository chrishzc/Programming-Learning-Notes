## 傳輸協定

### TCP — 可靠傳輸

**TCP（Transmission Control Protocol）** 是需要「先建立連線、確保每個封包都送到」的傳輸協定。

| 特性 | 說明 |
|------|------|
| 傳輸方式 | 連線導向，三次握手後才傳資料 |
| 可靠性 | ✅ 保證送達、保證順序 |
| 掉包處理 | 自動重新傳送 |
| 速度 | 較慢（確認機制有開銷）|
| 典型應用 | HTTP/HTTPS、SSH、資料庫連線、檔案傳輸 |

**三次握手（Three-way Handshake）**：

```
Client          Server
  │── SYN ──────▶│   我想連線
  │◀── SYN-ACK ──│   好，我收到了
  │── ACK ───────▶│   我知道你收到了
  │════════════════│  開始傳資料
```

> DevSecOps 關聯：HAProxy 可以在 L4（TCP 層）代理資料庫流量，無需解密 TLS。

---

### UDP — 快速但不可靠

**UDP（User Datagram Protocol）** 不建立連線，直接把資料「丟出去」，速度快但不保證送達。

| 特性 | 說明 |
|------|------|
| 傳輸方式 | 無連線，直接發送 |
| 可靠性 | ❌ 不保證送達、可能亂序 |
| 掉包處理 | 丟了就丟了，不重傳 |
| 速度 | 快（無確認開銷）|
| 典型應用 | DNS 查詢、語音通話（VoIP）、線上遊戲、直播串流 |

**TCP vs UDP 一句話比較**：

| | TCP | UDP |
|--|-----|-----|
| 比喻 | 掛號快遞（一定到）| 廣播傳單（有些會漏）|
| 犧牲 | 速度 | 可靠性 |
| 選哪個 | 資料不能錯 → TCP | 即時性 > 完整性 → UDP |

> DevSecOps 關聯：K8s NetworkPolicy 可分別對 TCP 和 UDP 設定放行規則（例如放行 DNS 需要允許 UDP 53）。

---

### DNS — 網路的電話簿

**DNS（Domain Name System）** 把人看得懂的網域名稱（`example.com`）翻譯成機器能用的 IP 地址（`93.184.216.34`）。

```
你輸入 google.com
      │
      ▼ UDP 53 port
   DNS 伺服器
      │
      ▼
   142.250.xxx.xxx  ← 這才是瀏覽器實際連線的地址
```

> DevSecOps 關聯：K8s 啟用 Default-Deny-All NetworkPolicy 後必須顯式放行 DNS（UDP/TCP 53），否則 Pod 無法解析任何服務名稱。詳見 [06 筆記](./06-K8s零信任網路策略.md)。

## TLS / HTTPS 相關

> TLS 的完整說明在 [03 筆記 §1.4](03%20·%20邊界防禦：反向代理選型與硬化實務.md)，這裡只列快速參考。

### TLS 版本速查

| 版本 | 現況 | 說明 |
|------|------|------|
| SSL 2.0 / 3.0 | ❌ 禁用 | 根本性設計缺陷，POODLE 攻擊 |
| TLS 1.0 / 1.1 | ❌ 禁用 | BEAST 攻擊，RFC 8996 棄用 |
| TLS 1.2 | ✅ 可用 | 搭配安全 Cipher 仍足夠 |
| TLS 1.3 | ✅ 推薦 | 最現代，移除所有已知弱演算法 |

### Let's Encrypt — 免費 TLS 憑證

**Let's Encrypt** 是由非營利組織 ISRG 運營的免費、自動化憑證頒發機構（CA）。

| 特性 | 說明 |
|------|------|
| 費用 | 完全免費 |
| 憑證類型 | DV（Domain Validated），只驗證你控制該域名 |
| 有效期限 | **90 天**（短期強制自動續期，降低洩漏風險）|
| 自動化工具 | **Certbot**（Nginx / Apache）、Caddy（內建）、Traefik（內建）|
| Wildcard 支援 | ✅（`*.example.com`，需 DNS-01 Challenge）|

**為什麼 90 天這麼短？**

> 憑證一旦洩漏，攻擊者可使用它偽裝成你的伺服器。90 天 = 就算洩漏，損害視窗最多 90 天。短期 + 自動化是安全設計，不是缺點。

**自動申請流程（ACME Protocol）**：

```
你的伺服器                    Let's Encrypt CA
    │── 申請 example.com 的憑證 ──▶│
    │◀── 請在這個 URL 放一個驗證檔 ──│  （HTTP-01 Challenge）
    │── 放好了 ───────────────────▶│
    │◀── 驗證通過，憑證核發 ─────────│
    │── 存下憑證，每 60 天自動續期 ──│
```

> DevSecOps 關聯：Traefik 和 Caddy 內建 Let's Encrypt 整合，`docker-compose` 加一行 label 即可全自動 HTTPS。Nginx 需配合 `certbot` 手動或排程續期。

### OCSP Stapling — 憑證吊銷驗證加速

**問題背景**：瀏覽器收到 TLS 憑證後，需要確認這張憑證沒有被吊銷（例如私鑰洩漏後 CA 會吊銷它）。傳統做法是瀏覽器每次連線都去查詢 OCSP（Online Certificate Status Protocol）伺服器，這會：
1. 增加延遲（要多一次網路請求）
2. 洩漏你的使用者在訪問哪個網站（隱私問題）

**OCSP Stapling 的解法**：

```
傳統方式：
Browser → Server（TLS 握手）
Browser → CA 的 OCSP 伺服器（另外查詢憑證是否有效）← 多一次延遲

OCSP Stapling：
Server 定期自己去 CA 查詢 OCSP 回應，並把回應「附在（Staple）」TLS 握手中
Browser → Server（TLS 握手 + 已包含 OCSP 回應）← 一次搞定
```

| 比較 | 傳統 OCSP | OCSP Stapling |
|------|-----------|---------------|
| 查詢方 | 瀏覽器 | 伺服器 |
| 延遲 | 多一次 RTT | 無額外延遲 |
| 隱私 | CA 知道誰訪問你的站 | CA 不知道個別使用者 |
| Nginx 設定 | — | `ssl_stapling on;` |

```nginx
# Nginx 啟用 OCSP Stapling
ssl_stapling on;
ssl_stapling_verify on;
resolver 8.8.8.8 1.1.1.1 valid=300s;  # 用來解析 CA 的 OCSP 端點
```

## 網路架構

### CDN — 內容交付網路

**CDN（Content Delivery Network）** 是分布在全球各地的伺服器節點網路，把你的內容複製到距離使用者最近的節點，縮短傳輸距離。

```
沒有 CDN：
台灣使用者 ──────────────────────▶ 美國原始伺服器
（延遲：150–200ms）

有 CDN：
台灣使用者 ──▶ CDN 台灣節點（快取）
（延遲：5–20ms，如果快取命中）
                   ↑
            只有快取未命中才去
            ──────────────────▶ 美國原始伺服器
```

**CDN 提供的不只是加速**：

| 功能 | 說明 |
|------|------|
| **靜態資源快取** | HTML、CSS、JS、圖片不用每次都打到原始伺服器 |
| **DDoS 防護** | 流量先打到 CDN 節點，超大流量被 CDN 吸收 |
| **WAF 整合** | Cloudflare 等 CDN 同時提供 WAF 功能 |
| **隱藏原始 IP** | 攻擊者只知道 CDN 的 IP，無法直打你的伺服器 |
| **TLS 終端** | CDN 統一管理憑證，原始伺服器不需要 |

**主流 CDN 服務**：

| 服務 | 特色 |
|------|------|
| **Cloudflare** | 免費方案即含 DDoS + WAF，最常用 |
| **AWS CloudFront** | 深度整合 AWS 生態（S3、ALB、Lambda@Edge）|
| **Fastly** | 高度可程式化（VCL / Compute@Edge）|
| **Akamai** | 企業級，最大規模 |

> DevSecOps 關聯：在 03 筆記的方案比較中，Cloudflare 是「CDN + 反向代理 + WAF + DDoS 防護」的全合一方案。見 [03 筆記 §2 Cloudflare](03%20·%20邊界防禦：反向代理選型與硬化實務.md)。

### DDoS — 分散式阻斷服務攻擊

**DDoS（Distributed Denial of Service）** 是攻擊者控制大量殭屍機器，同時向目標發送海量請求，把伺服器資源耗盡，讓正常使用者無法使用。

```
殭屍機器 1 ──┐
殭屍機器 2 ──┤
殭屍機器 3 ──┼──▶ 目標伺服器（資源耗盡，正常用戶無法連線）
殭屍機器 4 ──┤
殭屍機器 N ──┘
```

**DDoS 攻擊類型**：

| 類型 | 攻擊層次 | 範例 | 防禦方式 |
|------|---------|------|---------|
| **容量型（Volumetric）** | L3/L4 | UDP Flood、ICMP Flood | CDN 吸收、上游 ISP 過濾 |
| **協定型（Protocol）** | L4 | SYN Flood、Ping of Death | 速率限制、SYN Cookie |
| **應用層型（Application）** | L7 | HTTP Flood、Slowloris | WAF、速率限制、Bot 偵測 |

**Slowloris（慢速攻擊）**：
> 攻擊者開啟大量連線，故意以極慢速度送請求標頭，讓伺服器的連線槽被佔滿而無法接受新連線。Nginx 的 `client_header_timeout` 設定可防禦此攻擊。

**防禦層次（縱深防禦）**：

```
攻擊流量
    │
    ▼ 第一層：CDN（Cloudflare 等）— 吸收 L3/L4 大流量
    │
    ▼ 第二層：反向代理速率限制 — 限制每 IP 請求頻率
    │
    ▼ 第三層：WAF — 過濾 L7 應用層惡意請求
    │
    ▼ 應用伺服器（正常流量到這裡才需處理）
```

## 安全工具

### WAF — Web 應用程式防火牆

**WAF（Web Application Firewall）** 在 HTTP 應用層（L7）分析請求語意，阻斷 SQL 注入、XSS、惡意爬蟲等攻擊。

**WAF vs 反向代理 vs 防火牆**：

| | 傳統防火牆 | 反向代理 | WAF |
|--|-----------|---------|-----|
| 運作層 | L3/L4（IP + Port）| L4–L7 | L7（HTTP 語意）|
| 看什麼 | IP 位址、Port | 連線數、請求大小 | HTTP 路徑、參數、Body 內容 |
| 防什麼 | 非法 IP 連線 | DoS、緩衝區溢位 | SQLi、XSS、Bot、零日漏洞 |

> WAF 的完整實踐（WAF-as-Code、Terraform、AWS WAFv2）請見 **[04 筆記](./04-WAF-as-Code實踐.md)**。

## 容器架構模式

### Sidecar — 邊車容器模式

**Sidecar** 是一種容器設計模式：在主應用容器旁邊，再掛一個「輔助容器」，兩者共享同一個 Pod 的網路命名空間與儲存卷，但職責分離。

```
┌─────────────────── Kubernetes Pod ───────────────────┐
│                                                       │
│  ┌─────────────────┐    ┌────────────────────────┐   │
│  │  主應用容器       │    │  Sidecar 容器           │   │
│  │  (Node.js API)  │    │  (Envoy Proxy / 日誌收集) │  │
│  │                 │    │                        │   │
│  │  只處理業務邏輯   │    │  處理橫切關注點           │   │
│  └─────────────────┘    └────────────────────────┘   │
│         │ 共享 localhost 網路                          │
└─────────────────────────────────────────────────────-┘
```

**Sidecar 的典型用途**：

| 用途 | 工具 | 說明 |
|------|------|------|
| **Service Mesh 代理** | Envoy（Istio 注入）| 接管所有進出流量，實現 mTLS、流量追蹤 |
| **日誌收集** | Fluentd / Filebeat | 讀取主容器日誌檔並轉發到 Elasticsearch |
| **指標收集** | Prometheus Exporter | 將應用的指標轉換為 Prometheus 格式 |
| **憑證管理** | cert-manager agent | 自動輪換 TLS 憑證，不需重啟主應用 |

**好處**：主應用容器不需要自己處理日誌、監控、TLS 等橫切關注點（Cross-cutting Concerns），維持單一職責。

> DevSecOps 關聯：Istio Service Mesh 使用 Envoy 作為 Sidecar 自動注入每個 Pod，實現服務間 mTLS（零信任）而不需修改應用代碼。見 [06 筆記](./06-K8s零信任網路策略.md)。
