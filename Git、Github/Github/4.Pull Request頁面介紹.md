### Pull Request 的標準四部曲

1. **🌿 開闢新分支（Branch）並動工**： 你不在 `main` 大樓本體直接施工。你在旁邊開闢一個專屬的「獨立實驗室（分支）」，在裡面寫好你的程式碼。
    
2. **🚀 推送上雲端（Push）**： 你在本機電腦寫完後，用力按下 **Push**，把這個帶著新成果的分支「發射」送到 GitHub 總部的材料架上。
    
3. **📝 提出變更請求（Pull Request）**： 你在 GitHub 上點擊 **Create Pull Request**，填寫變更申請書，大喊：「我改好警報網頁了，請求歸隊合併！」這時就會進入我們剛剛看到的 PR 審查廣場。
    
4. **🕵️‍♂️ 審核與大功告成（Review & Merge）**： 團隊夥伴過來檢查程式碼（Review），確定沒問題後，按之下 **Merge**，你的新分支就會「啪」的一聲，正式融入 `main` 主大樓，這趟旅程就完美結案了！

### 1. 🔍 頂部萬能過濾器（Filters）

- **畫面想像**：這是一台「安檢名單顯示器」。目前上面預設顯示 `is:pr is:open`（只顯示開著、還沒合併的申請書）。
    
- **你可以怎麼改（物理畫面變化）**：
    
    - **想看過去的施工歷史**：點擊旁邊的 `✓ 1 Closed`（或是把輸入框改成 `is:pr is:closed`），畫面就會「啪」的一聲，把過去已經順利融入大樓、或是被退件的申請書全部調出來。這非常重要，因為**看以前的人怎麼改程式，是新手最快進入狀況的方法**。
        
    - **只想看自己送的申請**：在輸入框後面多打一個 `author:@me`，畫面上就只會留下你自己的變更申請書，不怕被別人的檔案淹沒。
        

### 2. 📑 橫向篩選下拉選單（Author, Label, Projects, Milestones, Reviews, Assignee）

- **畫面想像**：這排按鈕就像是「安檢官的分類夾」。
    
- **核心功能**：
    
    - **Reviews（審查狀態）**：你可以過濾出「哪些 PR 已經被點讚同意（Approved）了」，或是「有哪些還卡著需要有人去檢查（Review required）」。
        
    - **Labels / Milestones / Projects**：跟 Issues 頁面一模一樣！你可以一鍵找出「這個月大驗收（Milestone）到底包含了哪幾份代碼申請書」，或是「哪幾份代碼是屬於新增功能（feature）的變更」。
        

### 3. ⌨️ 鍵盤俠專屬快捷鍵提示（ProTip!）

- **畫面想像**：大螢幕最下方有一行不起眼的小字寫著：_ProTip! Type g p on any issue or pull request..._
    
- **核心功能**：GitHub 其實內建了「總部傳送門快捷鍵」。未來不論你點進哪一個複雜的程式碼討論頁面，只要在鍵盤上連續按下 **`g`** 然後按下 **`p`**（Go to Pull requests 的意思），你的畫面就會像瞬間移動一樣，直接秒切回現在這個 PR 主廣場！
