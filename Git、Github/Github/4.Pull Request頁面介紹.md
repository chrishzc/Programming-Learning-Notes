# GitHub Pull Request 頁面功能介紹

> [!ABSTRACT]
> 本篇整理 GitHub Pull Request（PR）的標準工作流程四部曲，以及 PR 列表頁面的篩選器與右側欄審查功能說明。

---

## 一、 Pull Request 標準四部曲

PR 是多人協作的核心流程，用於讓他人審查你的代碼變更後再合併至主分支。

1.  **🌿 開闢新分支並開發**：在本地從 `main` 分支切出一個功能分支（如 `feat/login`），在裡面完成開發後 commit。
    ```bash
    git checkout -b feat/login
    # ... 開發 ...
    git add .
    git commit -m "feat: 新增登入功能"
    ```

2.  **🚀 推送分支至遠端**：將功能分支推送到 GitHub。
    ```bash
    git push -u origin feat/login
    ```

3.  **📝 在 GitHub 上建立 PR**：GitHub 通常會自動提示你為剛推送的分支建立 PR。填寫標題與說明，說明這次變更的目的與範圍，點擊 `Create Pull Request`。

4.  **🕵️ Code Review 與 Merge**：團隊成員審查程式碼（Review）、留下意見，確認無誤後按下 `Merge pull request`，分支代碼正式融入 `main`。

> [!TIP]
> Merge 完成後，可以安全地刪除功能分支（GitHub 會自動提示 `Delete branch` 按鈕）。

---

## 二、 PR 列表頁面篩選功能

*   **頂部篩選列**：預設顯示 `is:pr is:open`（所有開啟中的 PR）。
    *   切換至 `Closed` 可查看已合併或已拒絕的歷史 PR，是了解過去代碼演進的好方式。
    *   加入 `author:@me` 可快速過濾出自己提交的 PR。

*   **橫向下拉篩選器**：
    *   **Reviews**：篩選審查狀態（`Approved` / `Review required` / `Changes requested`）。
    *   **Labels / Milestones / Projects**：與 Issues 頁面一致，跨維度過濾 PR。
    *   **Assignee / Author**：依負責人或提交者篩選。

*   **快捷鍵提示**：在任何頁面按下 **`g`** 再按 **`p`**（Go to Pull requests），可瞬間跳回 PR 主列表頁面。

---

## 三、 PR 詳細頁面的審查功能

進入單一 PR 後，右側欄提供以下操作：

*   **Reviewers**：指定或請求特定人員進行 Code Review。
*   **Assignees**：指定 PR 的負責人（通常是提交者自己）。
*   **Labels / Projects / Milestones**：與 Issue 一樣，可進行分類標記與進度連結。
