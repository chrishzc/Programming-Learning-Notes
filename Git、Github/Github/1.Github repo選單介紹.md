### 1. 📁 Code（代碼實體店 / 工程現場）

- **畫面想像**：這是總部的中央大螢幕，畫面上是一座正在蓋的大樓，看得到每一塊磚頭、鋼筋（程式檔、資料夾）是怎麼堆疊的。
    
- **核心功能**：
    
    - **看進度**：顯示目前專案裡所有的程式碼檔案。
        
    - **看說明書**：通常下方會直接攤開一本大大的 `README.md`（專案說明書），告訴你這個工程在幹嘛、要怎麼安裝使用。
        
    - **下載打包**：右上角有一個綠色的 `Code` 按鈕，就像一個「打包傳送門」，點下去就能把整棟大樓的設計圖與材料（程式碼）下載到你電腦裡。
        

### 2. ❓ Issues（問題回報區 / 意見看板）

- **畫面想像**：這是一面貼滿黃色便利貼的「意見反饋牆」。只要施工現場有人發現「天花板漏水了（Bug）」或是提議「這裡加個噴水池會更好（新功能需求）」，就會寫一張便利貼貼上來。
    
- **核心功能**：
    
    - **抓蟲與提需求**：任何人都可以來這裡「開一個 Issue（提問）」，大家會在下面留言討論該怎麼修。
        
    - **發派任務**：工頭（專案管理員）可以把某張便利貼指派給特定的工人（開發者）去處理，解決了就把便利貼撕掉（Close）。
        

### 3. 🔀 Pull requests (PR)（施工變更審查處）

- **畫面想像**：這是一個「嚴格的查驗關卡」。工人不能擅自把磚頭疊到大樓（主程式）上。他必須在旁邊的臨時小棚子改好後，寫一份「施工變更申請書（Pull Request）」，大喊：「**我改好了，請求把我的進度合併進去！**」
    
- **核心功能**：
    
    - **代碼審查（Code Review）**：其他工程師會在這裡吹毛求疵地檢查他改的程式碼，確定沒問題後，按之下 `Merge`（合併），這些新程式碼才會真正融入到 `Code` 的大樓裡。
        

### 4. ⚙️ Actions（自動化加工廠 / 機器人流水線）

- **畫面想像**：這是一條自動化傳送帶。只要有人提交了新代碼，傳送帶就會自動啟動，機器人會跑過來幫忙「檢查有沒有對齊（測試程式）」、「刷油漆（格式化）」、「打包裝箱（部署上線）」。
    
- **核心功能**：
    
    - **CI/CD（持續整合與部署）**：不用人工手動檢查，設定好腳本後，每次程式更新，GitHub 的伺服器就會自動幫你跑測試，確保新來的程式碼沒有把大樓搞垮。
        

### 5. 📊 Projects（工程進度看板 / 甘特圖）

- **畫面想像**：這是一個超大的「待辦事項白板」，分成「準備做（To Do）」、「正在做（In Progress）」、「做完了（Done）」。
    
- **核心功能**：
    
    - **團隊管理**：把前面的 Issues 和 Pull Requests 變成一張張卡片，在白板上移來移去，讓所有人一眼就看出整個工程目前的進度走到哪裡。
        

### 6. 🛡️ Security（安全安檢室）

- **畫面想像**：這是一群穿著西裝的安檢人員，拿著金屬探測器在檢查大樓。
    
- **核心功能**：
    
    - **漏洞掃描**：會自動檢查你用的建材（第三方套件）有沒有過期、或是藏有安全漏洞，甚至會提醒你是不是不小心把總部的保險箱密碼（API Key）寫進程式碼裡漏出去了。
        

### 7. 📈 Insights（數據統計分析室）

- **畫面想像**：這是一個掛滿統計圖表的數據分析牆。
    
- **核心功能**：
    
    - **看誰最賣力**：圖表會顯示這週誰搬了最多磚（Commit 最多）、大家都在幾點施工、這棟大樓被多少人關注（Stars）或複製（Forks）了。
