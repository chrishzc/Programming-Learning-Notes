# GitHub Actions 頁面功能介紹

> [!ABSTRACT]
> 本篇介紹 GitHub Actions 的核心概念（CI/CD 自動化流水線），說明 Workflow 的觸發機制、頁面結構與設定方式。

---

## 一、 GitHub Actions 是什麼？

GitHub Actions 是 GitHub 內建的 CI/CD（持續整合 / 持續部署）自動化平台。你可以設定**觸發條件**（如每次 Push 或提出 PR），讓 GitHub 的伺服器自動執行預先定義好的工作流程（Workflow）。

常見的自動化工作：
*   **自動測試（CI）**：執行單元測試，確保新提交的代碼沒有破壞既有功能。
*   **格式與語法檢查**：自動跑 linter，維持代碼風格一致。
*   **自動部署（CD）**：測試通過後，自動將最新版本部署到伺服器或雲端平台（如 Vercel、AWS）。

執行結果會以 **🟢 Success** 或 **🔴 Failed** 顯示在 Actions 頁面與 PR 頁面上。

---

## 二、 Workflow 設定方式

Workflow 的設定檔是一個 **YAML 檔**，必須放在 Repo 內的特定路徑：

```
.github/
└── workflows/
    └── your-workflow.yml
```

### 基本 YAML 結構範例
```yaml
name: Run Tests           # Workflow 名稱

on:                       # 觸發條件
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:                   # Job 名稱
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4         # 取得程式碼
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run tests
        run: pytest
```

## 三、 Actions 頁面結構說明

*   **左側 Workflows 清單**：列出這個 Repo 中所有已設定的 Workflow 名稱，點擊可過濾只看該 Workflow 的執行紀錄。

*   **主區域執行紀錄（Runs）**：每一列代表一次 Workflow 的執行，顯示：
    *   觸發事件（Push / PR）與提交訊息。
    *   執行者（哪個帳號觸發）。
    *   執行時間與耗時。
    *   結果狀態（🟢 Success / 🔴 Failed / 🟡 In Progress）。

*   **推薦 Workflow（頁面為空時）**：若 Repo 中尚未設定任何 Workflow，GitHub 會根據偵測到的程式語言推薦適合的入門 Workflow 藍圖（如 Python application、Node.js）。點擊 `Configure` 即可快速生成設定檔。

> [!TIP]
> 設定好 Actions 後，每次提出 PR 時，對應的 Workflow 執行結果會直接顯示在 PR 頁面，讓審查者一眼確認代碼品質。
