# GitHub Projects 頁面功能介紹

> [!ABSTRACT]
> 本篇介紹 GitHub Projects 的用途與頁面功能，說明如何將 Issues 和 Pull Requests 整合進看板進行任務進度管理，並比較 Projects 與 Issues 的核心差異。

---

## 一、 GitHub Projects 是什麼？

GitHub Projects 是一個跨 Repo 的任務進度管理面板（類似 Trello / Notion 看板）。它將 Issues 和 Pull Requests 轉化為卡片，並提供多種視圖方式追蹤整體開發進度。

它最大的優點是**即時同步**：當某個 Issue 被關閉或 PR 被合併，看板上的卡片狀態也會自動更新，不需要人工重複填寫進度表。

---

## 二、 Projects 頁面操作

*   **`New project`（建立新看板）**：從零建立一個全新的空白看板，選擇視圖類型（Kanban / Table / Roadmap）後開始使用。

*   **`Link a project`（連結現有看板）**：若組織內已有共用的看板，可以將其連結到這個 Repo，讓 Repo 的 Issues 和 PR 都能出現在那個看板上。

*   **搜尋框 `Search by name...`**：當關聯的看板數量多時，可輸入名稱快速找到特定看板。

*   **`Open` / `Closed` 狀態切換**：過濾顯示仍在進行中（Open）或已結束封存（Closed）的看板。

*   **左側欄（`Views`, `Milestones`, `Labels`）**：切換視圖、管理里程碑與標籤等輔助功能。

---

## 三、 Issues vs. Projects 核心差異

| **功能** | **Issues（任務卡片）** | **Projects（進度看板）** |
| :--- | :--- | :--- |
| **視角** | **微觀**：單一任務的討論與追蹤 | **巨觀**：整體進度的全局視野 |
| **關注焦點** | 這件事「要做什麼」？有哪些細節？ | 「進行到哪裡」了？誰卡住了？ |
| **跨 Repo** | 一個 Issue 屬於單一 Repo | 一個 Project 可以跨多個 Repo，統整所有相關任務 |
| **呈現方式** | 條列式清單 | 看板（Kanban）、時間軸（Gantt）、詳細表格（Table）|

> [!NOTE]
> 實際使用方式：在 Issues 頁面建立具體任務，再透過 Projects 看板追蹤這些任務的整體進度狀態。
