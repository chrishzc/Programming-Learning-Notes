# MCP 客戶端與伺服器 (MCP Client & MCP Server)

> [!ABSTRACT]
> 對比 MCP 客戶端與伺服器在職責、運作機制與部署位置上的差異，並深入解析 MCP + 代碼模式如何透過邊緣端計算節省 98.7% 的 Token 成本。

---

## 一、 核心角色與定位的差異

- **MCP 客戶端 (Client)**：扮演的是「大腦翻譯官、看守所長與協調者」。它位於 MCP 主機（Host，如 Cursor、Claude Desktop 或你寫的 Python 主程式）內部，活在 **macOS 原生系統（沙盒外面）**。它負責維護對話視窗（Context Window），將 LLM 的意圖翻譯成 MCP 指令，並擁有跟雲端大腦（API Key）與網路通訊的特權。
    
- **MCP 伺服器 (Server)**：扮演的是「技能提供者與傳話筒」。它是提供具體功能（如連接 Postgres、Slack 或 執行沙箱）的外部服務，負責宣告自己擁有的工具（Tools）與資源（Resources）。
    

## 二、 運作機制與職責的差異表

|**功能維度**|**MCP 客戶端 (Client) ── 沙盒外面**|**MCP 伺服器 (Server) ── 橋樑/插件**|
|---|---|---|
|**主動/被動**|**主動方**：負責發現伺服器、向伺服器請求工具清單，並在需要時發起工具調用指令。|**被動方**|
|**數據處理**|負責**上下文與資安管理**，將工具定義載入 LLM 視窗，攔截並審查高風險操作（如 L3 級別的核准攔截）。|負責**業務邏輯的調度**。它本身不包含 LLM，而是負責調用本地資源（如資料庫、檔案系統、Docker API）。|
|**傳輸協定**|實作 JSON-RPC 2.0 的傳輸管理，處理 Stdio 或 SSE（Server-Sent Events）的連接。|遵循 JSON-RPC 2.0 規範來回應請求並回傳結構化數據。|

## 三、 部署位置與連通性之工程實相

- **客戶端**：必須活在**沙盒外面**。否則一旦關進監獄，將失去外網通訊權限（無法呼叫雲端 LLM API）與安全護欄（Guardrails）的監管能力。
    
- **伺服器**：具有極高的靈活性。它可以是本地（Local）運行的輕量化腳本（適合處理私有文件），也可以是遠端（Remote）的雲端服務（適合連接公用 API，如天氣或股價）。
    
- **執行沙盒環境（Sandbox）**：活在**最底層的隔離監獄（如 Docker 容器、暫存資料夾）**。髒數據（如 50MB 的回測日誌）與待執行的 Python 腳本會被關在這裡默默打工，隨時準備在完工後被無情拋棄與銷毀。
    

## 四、 記憶優化策略：傳統模式 vs 現代代碼模式（省下 98.7% Token 的真相）

### 傳統客戶端特性與限制

- **預先加載（Upfront Loading）**：傳統客戶端通常會在連線一開始，就將伺服器提供的所有工具定義全部載入 LLM 的上下文視窗中。
    
- **上下文膨脹風險**：當連接多個包含數百個工具的伺服器，或嘗試處理大型數據時，會將大量原始數據（如 50MB 日誌）一股腦塞進對話歷史（Shared Context），導致 LLM 消耗數十萬個 Token，費用暴增且極易幻覺。
    

### 現代進階優化：MCP + 代碼模式（[[code 模式|Code Mode]]）

- **核心思維**：**「用『代碼（Code）』去就近親近『數據（Data）』，而不要把『數據』搬運給『大腦（LLM）』。」**
    
- **具體做法**：大腦（Client）不再向伺服器索取原始大數據。大腦自己編寫一段原生的 Python 腳本（代碼模式，約 500 Token），透過 [[Function Calling timing|Function Calling]] 將腳本打包發送給 **MCP Server**。
    
- **邊緣端無情執行**：MCP Server 收到後，轉身命令本地的 **Docker 引擎** 開啟隔離容器，腳本直接在你的 Mac 本地 CPU/記憶體中對 50MB 數據進行無情清洗與計算。
    
- **精簡回傳**：計算完畢後，只將篩選出的最後 5 行黃金數據（約 100 Token）回傳給大腦。原本需要 15 萬 Token 的任務瞬間縮減至 2,000 個，**顯著節省 98.7% 的空間與成本**。
    

## 五、 💡 2026 行業新趨勢：Docker 官方 MCP Toolkit 革命

在現代工業級開發中，MCP Server 本身預設是「不會」也「沒資格」凭空生出 Docker 的，它必須依賴本地開著的 Docker Desktop（Docker Daemon）。

為了極致的安全與無腦部署，目前的標準實作已演進為 **Docker MCP Toolkit 架構**：

1. **全面容器化**：連 MCP Server 本身，都會被打包成一隻安全的 Docker 容器在背景運行。
    
2. **一鍵管理**：開發者直接在 Docker Desktop 的圖形介面中管理、點選並下載各種開源 MCP 插件（如 GitHub、PostgreSQL）。
    
3. **無痛控制**：MCP Server 作為「拿著特許證明的通訊官」，透過安全通道控制 Docker 引擎，實現高效率、自動化的「開門、關門、洗資料、銷毀監獄」完整生命週期。
    

## 六、 總結

**MCP 客戶端是負責「對內管理大腦（LLM）與上下文」，而 MCP 伺服器是負責「對外作為橋樑去調度 Docker 與數據資源」。** 兩者透過標準化的 JSON-RPC 契約協作，讓[[生成式 AI、LLM 概論|大語言模型]]從一個只能文字聊天的機器人，徹底蛻變為能夠在邊緣端發動無情計算的工業級自動化大腦。
