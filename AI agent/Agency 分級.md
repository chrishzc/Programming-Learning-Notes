# AI Agent Agency 分級

> [!ABSTRACT]
> 整理 AI Agent 的 5 階 Agency 分級，並深入探討 L3 與 L4 級別在攔截機制、錯誤處理與自我修正等底層工程技術上的本質差異。

---

## 一、 AI Agent 的 5 階 Agency 分級圖

| -------------- | ------------------------------------ | -------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| **L1**         | **單純工具 (Tools)**                     | 沒有大腦。輸入 A 固定輸出 B。                                                                | **操作者**                                                   | 傳統的 Python 下單腳本。                                                           |
| **L2**         | **協同者 (Co-Pilot)**                   | 有大腦。能幫你寫 Code 或找 [[RAG|RAG]] 知識，但不會幫你按執行鍵。                                               | **主導者與審查者**                                               | Cursor 編輯器、Copilot 聊天視窗。                                                   |
| **L3**         | 條件自動化<br><br>(Conditional Agency)    | **具備單一任務的 [[1.ReAct|ReAct 循環]]**。<br><br>能自主想、動、看、改，但遇到邊界模糊或高風險操作（如扣款）時，必須停下來等人類 OK。         | **監管者 (Human-in-the-Loop)**<br><br>坐在副駕駛座，負責按「Approve」綠鍵。 | **AI 投顧特助**：自己查完 BTC 指標，寫好交易計畫，跳出視窗問你：「我預計買入 0.1 顆，請問同意執行嗎？」               |

## 二、 L3 與 L4 Agency 的底層工程技術差在哪？

當你從開發一個 L3 的 Agent 要升級到 L4 時，你身為工程師，代碼的架構會發生重大的變革：

### 攔截機制（Interrupt Mode）的改變

- **L3 Agency**：在你的 **[[Function Calling timing|Function Calling]]** 邏輯裡，只要 [[生成式 AI、LLM 概論|LLM]] 決定呼叫 `place_order_api`，後端程式碼會強制作動一個攔截器（Breakpoint），把 JSON 暫存在記憶體裡，並發送一個 Webhook 給人類的 Line 或是前端介面，直到人類回覆 `YES`，程式碼才往下走。
    
- **L4 Agency**：不再需要每步攔截。你改用我們之前聊過的 **[[Code as Executor|Code as Executor]]（代碼作為執行器）** 在最外層做一個「風控總管」。主程式直接設定硬性條件（例如：單筆虧損上限 2%），只要 AI 寫的 Code 或 Function 沒有突破這個安全護欄（Guardrails），沙箱和 API 就直接 24 小時無條件放行。
    

### 錯誤處理與容錯（Self-Healing）的韌性

- **L3 Agent**：如果跑 Code 出錯、或者 API 斷線，它 ReAct 了兩次發現搞不定，就會雙手攤開噴出 Error：「對不起，系統發生錯誤，請人類接管。」
    
- **L4 Agent**：具備強大的長週期記憶管理（Long-term State Management）與「超時降級機制」。如果交易所 API 斷線，它會自己記錄當前狀態，把任務放進佇列（Queue），寫腳本去測試備用節點，或者自己切換到「空倉避險模式」，嘗試自己活下去，直到真的發生毀滅性系統崩潰才回報。
