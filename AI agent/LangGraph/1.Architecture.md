# LangGraph 核心架構

> [!ABSTRACT]
> 本章深入剖析 LangGraph 的三大核心支柱：Nodes（節點）、Edges（連接通道，包含普通邊與條件邊 of 開發流派）以及 Shared State（共享狀態），奠定圖形編排狀態機的基礎。

---

## 🧱 LangGraph 核心三大支柱 (Architecture)

### 支柱一：Nodes (節點 ── 獨立的模組化節點)

- **圖上寫什麼**：`Processing functions`（處理函數）。
    
- **核心直覺**：**「獨立執行特定任務的模組化節點。」**
    
- **技術真相**：在 Python 程式碼裡，一個 Node 就是一個普通的 Python 函數。每個節點只負責一件極致單純的事（如：決策節點擬定策略、回測節點計算指標、下單節點呼叫 API）。
    
- **🚨 LLM 的物理實相**：**[[生成式 AI、LLM 概論|LLM]] 在圖裡沒有特權，==它只是被當作一項外部 API 工具，放進了特定的 Node 節點中執行==！** 當系統在回測節點跑幾十 MB 的數據時，[[生成式 AI、LLM 概論|LLM]] 根本沒被呼叫，完美實現**上下文隔離**，省下 98.7% Token。
    
- **黃金鐵律**：Nodes 之間絕對不能互相呼叫（節點 A 不能直接呼叫節點 B），必須保持完全的解耦。
    

### 支柱二：Edges (邊 ── 連接節點的單向通道)

- **圖上寫什麼**：`Control flow / transitions`（控制流 / 狀態轉移）。
    
- **核心直覺**：**「連接節點之間、定義執行順序的單向通道。」**
    
- **技術真相**：Edges 決定了程式的執行順序。在 LangGraph 裡分為兩大類：
    
    1. **普通邊 (Normal Edge)**：靜態流程定義。例如從 `回測節點` 出來，必須無條件走向 `決策節點`。
        
    2. **條件邊 (Conditional Edge)**：根據執行狀態動態決定下一個節點。本質上是一段純 Python 的 `if-else` 函數。
        
- **🛡️ 條件邊的兩大開發流派**：
    

##### 👑 流派 A：純 Python 邏輯判斷（零 Token 成本，高穩定度）

決策節點已配置 [[LangChain簡介#3. Parsers（輸出翻譯官 / 結構化合約）|Output Parser]]（結構化翻譯官），模型在節點中輸出的訊息已經是乾淨的 JSON 欄位（例如：`{"next_action": "trade"}`）並寫入狀態（State）。==條件邊函數完全不需要 [[生成式 AI、LLM 概論|LLM]]，純靠 Python 讀取欄位==。
```python
# 這是一段完全【沒有 LLM】的純 Python 條件邊函數
def decide_next_step(state: AgentState) -> str:
    # 1. 打開全域狀態，拿出模型剛剛在節點中洗乾淨的最後一則 JSON 訊息
    last_message = state['messages'][-1]
    
    # 2. 純 Python if-else 邏輯分流，速度極快，而且 0 Token 費用
    if "trade" in last_message.get("next_action", ""):
        return "call_tool_node"   # 導向工具執行節點
    else:
        return END                # 任務結束，收工
```

##### 流派 B：塞入輕量型 LLM 進行模糊語意判斷（適合模糊語意判斷）

決策節點輸出的資訊非常模糊、無法輕易被 JSON 結構化（例如智慧客服需要判定使用者的情緒「是不是真的憤怒到需要轉接人工」）。可在條件邊函數內部，單獨塞入一具輕量級模型（如本機免費的 [[LangChain簡介#2. Model（大腦接頭）|ChatOllama]]/Llama-3-8B）當守門員。
```python
# 這是一段【內含輕量 LLM】的條件邊函數
def decide_next_step_with_llm(state: AgentState) -> str:
    # 1. 拿出對話歷史
    last_message = state['messages'][-1].content
    
    # 2. 這裡單獨點名一具小模型（守門員）
    router_llm = ChatOllama(model="llama3:8b")
    
    # 3. 给守門員一個極短的分類 Prompt
    prompt = f"請分析以下文字是否包含強烈的退款意圖，請只回答 YES 或 NO：{last_message}"
    decision = router_llm.invoke(prompt).content
    
    # 4. 根據小大腦的分類結果進行路由
    if "YES" in decision.upper():
        return "human_customer_service_node"  # 走向人工客服節點
    return "auto_reply_node"                  # 走向自動回覆節點
```

### 支柱三：Shared State (共享狀態 ── 節點間傳遞的狀態資料結構)

- **圖上寫什麼**：`TypedDict`（帶有型別說明的 Python 字典）。
    
- **核心直覺**：**「所有節點共用的資料結構，負責維護執行過程中的全域狀態。」**
    
- **技術真相**：這是 LangGraph 最靈魂的發明，解決了傳統 [[AI Agent 概論|Subagents]]「資料斷層」的關鍵痛點。
    
- **運作機制**：當執行流進入節點 A 時，節點函數會讀取 State 中的歷史資料，進行計算。計算完畢後，節點函數回傳更新後的 State。當執行流順著 Edge 進入節點 B 時，節點 B 讀取的依然是同一個 State。
