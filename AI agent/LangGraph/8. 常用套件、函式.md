# LangGraph 常用套件與函式速查

> [!ABSTRACT]
> 本章彙整了 LangGraph 生態系中常用的延伸套件（如伺服器部署、持久化儲存、SDK 與預製組件）與核心 API 函式對照表，方便開發時快速檢索與調用。

---

## 1. 核心與延伸套件介紹 (Ecosystem Packages)

### 1.1 遠端部署與擴展：`langgraph-api` (LangGraph Cloud)

當你在本機用 Studio 測試完美後，下一步就是部署。`langgraph-api`（或稱 LangGraph Cloud / LangGraph Server）是官方專為圖形架構量身打造的後端伺服器套件。

- **實用點**：內建了**高併發的任務佇列（Queue）**與**持久化狀態管理**。當多個使用者同時呼叫你的 Agent 時，它會自動處理多執行緒（Concurrency）、鎖定機制（Preventing race conditions），確保同一個使用者的狀態不會被兩個併發的請求同時修改而崩潰。
- **整合**：完美支援串接生產環境的資料庫（如 PostgreSQL），拿來當作 Checkpointer（狀態存檔點）。

| **函式 / 類別名稱** | **使用用途** |
| :--- | :--- |
| **`langgraph dev`** | ==**啟動本機開發伺服器（推薦）**==。會自動掃描 `langgraph.json`，在背景拉起 Docker 環境並與 LangGraph Studio 介面連線。 |
| **`langgraph build`** | ==**打包生產環境映像檔**==。將你的 LangGraph 專案、依賴套件與設定直接打包成 Docker Image，方便部署到 AWS、GCP 等雲端平台。 |

### 1.2 生產級持久化記憶：`langgraph-checkpoint-postgres`

在記憶機制上，LangGraph 預設自帶 `MemorySaver`（記憶體存檔），但只要伺服器一重啟，記憶就全沒了。在生產環境中，官方推出了針對不同資料庫的專用記憶體持久化套件。

- **實用點**：如果你要在正式環境上線，**`langgraph-checkpoint-postgres`** 是最主流的選擇。它能把 Agent 執行的每一步（每個 Node 的 State、Thread ID、歷史紀錄）自動存入 PostgreSQL。
- **帶來的效益**：這就是實作「斷點續傳」與「跨幾天後的對話記憶」的核心套件。即使伺服器崩潰，重啟後 Agent 也能無縫從上一次死掉的地方爬起來繼續跑。

| **函式 / 類別名稱** | **使用用途** |
| :--- | :--- |
| **`PostgresSaver.from_conn_string(url)`** | ==**建立 Postgres 儲存器執行個體**==。利用資料庫連線字串（Connection String）初始化持久化層。 |
| **`memory.setup()`** | ==**自動初始化資料庫資料表（Schema）**==。在初次連線時，自動在你的 PostgreSQL 中建立儲存 Thread、Checkpoint、State 的所有必要資料表，免去手動寫 SQL 建立 Table 的麻煩。 |

### 1.3 多智能體通訊標準：`langgraph-sdk`

如果你不想直接對伺服器發送 raw HTTP 請求，官方提供了 Python 和 JavaScript 版本的 `langgraph-sdk`。

- **實用點**：當你把 Agent 部署到伺服器後，你的前端網頁、LINE Bot 或企業內部系統，可以直接透過這個 SDK 來調用遠端的 Agent。
- **核心功能**：它內建了極其重要的 **Streaming（串流）支援**。你可以輕易抓取 `stream_modes=["updates", "values"]`，讓前端即時更新「LLM 現在打字到哪裡」或是「現在換到哪一個節點正在執行（Node Updates）」。

| **函式 / 類別名稱** | **使用用途** |
| :--- | :--- |
| **`get_client(url="...")`** | ==**初始化 SDK 客戶端**==。傳入你部署好的 LangGraph API 伺服器網址，建立連線。 |
| **`client.assistants.search(...)`** | ==**尋找已部署的 Graph 類別**==。在伺服器上根據你在 `langgraph.json` 定義的名稱，抓取對應的 Agent 實例。 |
| **`client.threads.create()`** | ==**建立全新對話線程（Thread）**==。在遠端伺服器上開闢一個獨立的記憶空間，返回 `thread_id`，用來隔離不同使用者或不同次對話。 |
| **`client.runs.stream(thread_id, assistant_id, input)`** | ==**發起遠端串流執行（核心）**==。訂閱遠端 Agent 的即時運行狀態，能一邊執行一邊回傳當前是哪個 Node 在跑，以及 LLM 生成的即時文字塊（Chunks）。 |

### 1.4 工具調用加速器：`langgraph.prebuilt`

這不是獨立的安裝包，而是內建在 LangGraph 裡面的「預製常用組件」，但很多開發者一開始會漏掉它。

- **`create_react_agent`**：如果你只想做一個標準的 ReAct 架構（思考 -> 呼叫工具 -> 觀察 -> 再思考），你根本不需要自己手動刻 Node 和 Edge。直接用這個 prebuilt 函式，傳入 LLM 和一組 Tools，它會一秒幫你生出一個完美的循環圖架構，並自帶錯誤處理（如工具呼叫失敗時自動修正）。
- **`ToolNode`**：專門用來承接 LLM `tool_calls` 的標準節點，省去你自己寫迴圈去執行各個 Python Function 的麻煩。

| **函式 / 類別名稱** | **使用用途** |
| :--- | :--- |
| **`create_react_agent(model, tools)`** | ==**快速建立一個 ReAct 模型圖**==。只要提供支援 Tool Calling 的 LLM 模型與 Tools 列表，直接打包成一個包含「思考迴圈」的完美 Graph。 |
| **`ToolNode(tools)`** | ==**專用工具執行節點**==。這是一個包裝好的 Node 類別，當上一個節點傳來的 State 包含 `tool_calls` 時，它會自動解析、平行/依序呼叫對應的 Python 函式，並將結果回傳寫入 State。 |
| **`tools_condition(state)`** | ==**內建條件路由函式**==。通常與 `add_conditional_edges` 搭配。它會檢查 LLM 的回覆，如果包含工具調用就指引流程走往 `ToolNode`，如果 LLM 直接回答完畢，就指引流程走往 `END`。 |

### 1.5 終端除錯神兵：`grandalf`

如前章所提到的，如果你不方便啟動重型的 LangGraph Studio（例如在遠端 Linux 伺服器或純文字環境上除錯），可以安裝 `grandalf`。

- **實用點**：`grandalf` 本身是一個圖形佈局（Graph Layout）底層演算法套件。你**不需要單獨去呼叫 grandalf 的函式**，你只需要在環境中用 `pip install grandalf` 安裝它。
- **運作機制**：安裝後，LangGraph 內建的 `draw_ascii()` 就能在後台調用 `grandalf` 的計算能力，順利將你的 Nodes 和 Edges 換算成空間座標並在終端機中繪製出 ASCII 文字流程圖。

## 2. 常用 API 與核心函式對照表 (Core API Reference)

### 2.1 建立圖形架構與核心控制 (Core Graph & Control)

| **函式 / 類別名稱** | **所屬模組** | **主要使用用途** |
| :--- | :--- | :--- |
| **`StateGraph(state_schema)`** | `langgraph.graph` | ==**限制圖形共享狀態結構。**== 這是建立所有 LangGraph 工作流的起點，用來定義整個 Graph 共享的 `State`。 |
| **`START`** | `langgraph.graph` | ==**標記圖形進入點。**== 一個特殊的常數，用在 `add_edge(START, "node_name")`，指定工作流啟動時第一個要執行的節點。 |
| **`END`** | `langgraph.graph` | ==**標記圖形結束點。**== 用來告訴圖形當走到某個節點或某個條件成立時，整個工作流應該正式結束（Stop）。 |
| **`graph.add_node(name, action)`** | `graph 物件方法` | ==**新增流程步驟節點。**== 將一個 Python 函式或 Runnable 物件註冊為圖中的一個步驟（Node），並賦予它一個唯一的名稱。 |
| **`graph.add_edge(start, end)`** | `graph 物件方法` | ==**新增標準節點連線。**== 建立一條固定的單向通道，當 `start` 節點執行完畢後，直接進入 `end` 節點。 |
| **`graph.add_conditional_edges(...)`** | `graph 物件方法` | ==**新增條件式路由（Router）。**== 根據一個路由函式的判斷結果（例如判斷 LLM 是否想呼叫工具），動態決定下一步要走去哪一個節點。 |
| **`graph.compile(checkpointer, ...)`** | `graph 物件方法` | ==**編譯圖形為 Runnable。**== 將定義好的 Node 和 Edge 打包成一個可執行的應用程式。在此步驟可以加入中斷點（Interrupt）或記憶體儲存器。 |

### 2.2 持久化與記憶機制 (Persistence & Checkpointers)

| **函式 / 類別名稱** | **所屬模組 / 套件** | **主要使用用途** |
| :--- | :--- | :--- |
| **`MemorySaver()`** | `langgraph.checkpoint.memory` | **本機記憶體存檔點。** 最簡單 of Checkpointer，將對話歷史與節點狀態存在記憶體中。**適合開發測試**，伺服器重啟資料會消失。 |
| **`PostgresSaver(conn_string)`** | `langgraph_checkpoint_postgres` | **生產級 Postgres 存檔點。** 連接實體資料庫，將每次執行的 State 寫入硬碟。**適合正式上線**，實作跨日對話與斷點續傳。 |
| **`app.get_state(config)`** | `compiled_graph 物件方法` | **讀取當前執行狀態。** 傳入包含 `thread_id` 的設定，可以直接撈出該使用者目前走到哪一步、有哪些變數。 |
| **`app.update_state(config, values)`** | `compiled_graph 物件方法` | **手動竄改/更新狀態。** 這是實作「時光旅行」或「人工介入修改資料」的核心函式，能直接蓋掉原本的 State 變數。 |

### 2.3 官方內建的預製加速組件 (Prebuilt Components)

| **函式 / 類別名稱** | **所屬模組** | **主要使用用途** |
| :--- | :--- | :--- |
| **`create_react_agent(model, tools)`** | `langgraph.prebuilt` | **一鍵生成 ReAct 智能體。** 你不用自己刻 Node/Edge，只要給它大模型和工具清單，它會自動建立好一個「思考->呼叫工具->回復」的循環圖，初學者必用。 |
| **`ToolNode(tools)`** | `langgraph.prebuilt` | **自動工具執行節點。** 當大模型判定需要調用工具時（`tool_calls`），這個 Node 會自動幫你平行或依序執行綁定的 Python 函式，省去手動解包的麻煩。 |
| **`tools_condition(state)`** | `langgraph.prebuilt` | **工具判斷路由器。** 一個預寫好的條件路由函式，通常跟 `add_conditional_edges` 搭配，用來偵測 State 裡面有沒有包含工具呼叫請求，有就導向 `ToolNode`，沒有就導向 `END`。 |

### 2.4 圖像化與遠端呼叫 (Visualization & SDK)

| **函式 / 類別名稱** | **所屬模組 / 套件** | **主要使用用途** |
| :--- | :--- | :--- |
| **`app.get_graph().draw_mermaid()`** | `compiled_graph 物件方法` | **匯出 Mermaid 語法字串。** 可以直接把字串複製到 any 支援 Mermaid 的 Markdown 編輯器中渲染出架構圖。 |
| **`app.get_graph().draw_mermaid_png()`** | `compiled_graph 物件方法` | **將架構圖轉成 PNG 點陣圖資料。** 搭配 `grandalf` 套件，可以把流程圖下載存成實體圖片檔，或在 Jupyter 中顯示。 |
| **`get_client(url)`** | `langgraph_sdk` | **初始化 SDK 客戶端。** 讓前端、LINE Bot 或其他微服務連線到部署好的 LangGraph API 伺服器。 |
| **`client.runs.stream(...)`** | `langgraph_sdk` | **發起串流執行。** 透過 SDK 呼叫遠端 Agent 並訂閱事件。可以即時抓取 `values`（目前最新變數）或 `updates`（哪一個節點剛剛跑完），用來做前端的 Loading 動畫或即時打字效果。 |
