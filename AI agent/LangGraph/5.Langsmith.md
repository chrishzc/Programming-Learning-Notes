# LangSmith 監控與調試

> [!ABSTRACT]
> 本章介紹 LangSmith 在 Agent 開發中的監控與調校功能：包含端到端追蹤 (End-to-end tracing)、視覺化 Playground 除錯 (Studio)、黃金資料集自動化評估 (Evaluation) 與生產環境三商務指標監控，並說明本地 Docker 部署及 Python SDK 開發。

---

在傳統軟體工程中，我們有 APM 工具（如 DataDog、New Relic）來監控系統；而在 [[生成式 AI、LLM 概論|LLM]] 和 [[AI Agent 概論|Agent]] 的世界裡，**LangSmith 就是那套最強大的監控與調校儀表板**。

## 1. End-to-end tracing (Trace Trees / 端到端追蹤)

當你執行一個複雜的 [[1.Architecture|LangGraph]] 流程時，使用者輸入一句話，可能在圖裡面經過多次迭代、呼叫了 3 次不同的 [[生成式 AI、LLM 概論|LLM]]、執行了 2 次工具，最後才吐出答案。

- **痛點**：如果 AI 回覆品質不佳，你根本不知道是哪一個環節出錯了。是第 1 次 [[生成式 AI、LLM 概論|LLM]] 判斷錯？還是第 2 次工具抓錯資料？
    
- **解決方案**：LangSmith 內建自動追蹤（Tracing）。它會把這次執行的所有細節畫成一棵「追蹤樹（Trace Tree）」。你可以點開每一層，清清楚楚地看到：
    
    - 這個節點輸入了什麼 Prompt。
        
    - [[生成式 AI、LLM 概論|LLM]] 吐出了什麼原始字串。
        
    - 工具被調用時，傳入的 JSON 參數到底長怎樣。 有了這棵樹，大幅提升除錯效率，再也不用在 Python 程式碼裡編寫繁瑣的偵錯輸出了。
        

## 2. Visual debugging (LangSmith Studio / 視覺化除錯) $\rightarrow$ **（需訂閱/付費）**

這是一個對 Prompt 工程師或後端工程師極度友好的視覺化工作區（Playground）。

- **核心功能**：當你在 Trace Tree 裡發現：「啊！這個 Node 的 Prompt 寫得不好，導致 [[生成式 AI、LLM 概論|LLM]] 誤判了。」你**不需要**回到程式碼裡修改、重啟伺服器、再測試一次。
    
- **運作邏輯**：你可以直接在 LangSmith 網頁介面上，點擊該節點的 "Playground"，它會把你當下的那一副 Prompt 和上下文原封不動地搬進瀏覽器。你可以直接在網頁上改 Prompt、更換底層語言模型（例如從 GPT 改成 Claude），直接點擊執行（Run），直到測試出完美的輸出。確認沒問題後，再把這段新 Prompt 複製回程式碼中。
    

## 3. Evaluation (Datasets & LLM-as-judge / 評估系統) $\rightarrow$ **（需訂閱/付費）**

當你在本地端修改了某個 Prompt，你怎麼知道這個修改是「真的變好」，還是「修好了 A 卻改壞了 B」？在量化交易系統或複雜系統中，我們需要自動化測試（CI/CD），在 AI 領域這叫 **Evaluation（評估）**。

- **Datasets（資料集）**：你可以在 LangSmith 裡收集或手動建立一個「黃金標準資料集」（例如 100 道標準的加密貨幣用戶提問與正確答案）。
    
- **LLM-as-judge（LLM 作為裁判）**：當你更新了 Agent 系統，LangSmith 會自動幫你把這 100 道題目跑過一遍，並調用一個更強大的模型（如 GPT-4o 或 Claude 3.5 Sonnet）作為「裁判」，去對比你新系統的回答與標準答案是否語意相符、有沒有給予錯誤投資建議，最後量化出一個「正確率得分（Score）」。 這讓 Prompt 的優化從主觀判斷變成了「看數據說話」。
    

## 4. Production monitoring (Cost / Latency / Errors / 生產環境監控)

當你的 [[AI Agent 概論|Agent]] 服務正式上線、有成千上萬個用戶在用時，你最關心的三個商務指標就是：**所消耗的費用（Cost）**、**回應速度（Latency）**、以及**有沒有拋出異常（Errors）**。

- **Cost（成本）**：LangSmith 會自動幫你計算每次對話消耗了多少 Input/Output Tokens，並折算成美金。你能直接在儀表板看到今天消耗了多少費用。
    
- **Latency（延遲）**：你可以監控哪些節點（Nodes）跑得最慢。如果是某個 RAG 檢索花了 5 秒，你就能精準去優化那個特定資料庫的索引。
    
- **Errors（錯誤率）**：一旦有用戶在聊天時系統拋出異常（例如 API 金鑰過期、或是程式碼報錯），LangSmith 會立刻捕捉並歸類這些異常（Exceptions），讓你能在使用者寫信報怨前，搶先修好 Bug。
    

## 💡 最棒的是：它「幾乎不用改程式碼」

要啟用這麼強大的功能，在 [[1.Architecture|LangGraph]] 中非常簡單。你不需要在程式碼裡寫什麼複雜的 SDK。你只需要在你的系統環境變數（`.env`）中加上幾行設定：
```bash
export LANGCHAIN_TRACING_V2="true"
export LANGCHAIN_API_KEY="你的_langsmith_api_key"
export LANGCHAIN_PROJECT="我的_crypto_trading_bot"
```

只要這三行環境變數在，[[1.Architecture|LangGraph]] 在執行時就會**自動、在後台非同步地**把所有的軌跡（Traces）全部上傳到 LangSmith 的雲端儀表板上，完全不影響你原本程式的執行速度。


# 如何使用
## 網頁版 步驟一：去網頁端拿到你的 API 金鑰

LangSmith 是個雲端平台，你必須先去註冊一個帳號來建立你的專案儀表板。

1. 瀏覽 **[LangSmith 官網](https://smith.langchain.com/)**，用你的 GitHub 或 Google 帳號直接登入。
    
2. 進入後，點擊左下角的 **Settings（設定）**。
    
3. 找到 **API Keys** 區塊，點擊 **Create API Key**。
    
4. **複製這串金鑰**（它長得像 `lsv2_pt_...`）。_注意：它只會出現這一次，記得先貼到記事本存好。_
    

## 步驟二：在你的本地開發環境中「載入環境設定」

拿到 API 金鑰後，你有兩種方式可以啟動它（選擇其中一種即可，**最推薦方法 A**）：

### 方法 A：寫在 `.env` 檔案中（實務工程最推薦）

在你的 LangGraph 專案根目錄下，建立一個叫做 `.env` 的檔案，把下面這四行貼進去：
```bash
# 1. 告訴 LangGraph 引擎：開啟追蹤功能！
LANGCHAIN_TRACING_V2=true

# 2. 貼上你剛剛複製的 LangSmith API 金鑰
LANGCHAIN_API_KEY="lsv2_pt_你的金鑰"

# 3. 自定義你的專案名稱（LangSmith 網頁上會自動建立這個專案分類）
LANGCHAIN_PROJECT="my_crypto_agent"

# 4. (選填) 如果你有用 OpenAI 或 Anthropic，順便貼在這裡
OPENAI_API_KEY="sk-..."
```

當你在 Python 程式碼中利用 `python-dotenv` 套件載入這些變數後，**LangGraph 在背後只要一執行 `.invoke()` 或 `.stream()`，就會自動將追蹤數據發送至雲端，你什麼都不用多寫！**

### 方法 B：在執行程式前，直接在終端機（Terminal）手動輸入

如果你只是想臨時測試，不想寫檔案，可以直接在執行 Python 腳本前，在終端機輸入以下指令：
```bash
export LANGCHAIN_TRACING_V2="true"
export LANGCHAIN_API_KEY="lsv2_pt_你的金鑰"
export LANGCHAIN_PROJECT="my_crypto_agent"

# 接著直接執行你的 LangGraph 程式
python my_trading_bot.py
```

## 步驟三：去網頁上看成果

當你完成上述設定並跑了一次你的 LangGraph 程式碼之後：

1. 回到 LangSmith 網頁首頁。
    
2. 點擊左側的 **Projects**，你會看到畫面上多出了一個名為 `my_crypto_agent` 的專案。
    
3. 點進去，你剛剛執行的那次對話、呼叫了哪些 Node、用了什麼 Tool，就已經整整齊齊地變成一棵 **Trace Tree** 躺在裡面等著你分析了！

## 本地板
LangChain 官方有提供一個命令列工具，讓你可以在終端機直接追蹤或啟動本地服務：

如果你想把 LangSmith 的數據完全轉成本地端，甚至不想把數據傳上雲端網頁，你可以在本地 Docker 裡直接跑一個**完全開源、本地版的 LangSmith**。

在終端機輸入：
```bash
# 啟動本地測試伺服器
pip install langsmith
langsmith server start
```

這會直接在你的本機跑起一個本地的測試伺服器，它會把所有的 Trace 數據存在本機。雖然它還是會提供一個 `localhost:1984` 的本地網頁，但這代表你的數據**完全不需要傳上網**，安全且全部都在你本地的環境內。

## 2. 最自由的方式：直接用 Python 程式碼串 API 撈數據

如果你想把那些 Trace Tree、LLM 的 Token 消耗量、或是執行錯誤的訊息抓出來，寫成自動化腳本（例如定時統計今天交易機器人消耗了多少費用，並發送通知到你的系統），你可以直接用 **LangSmith Python SDK（這本質上就是串 API）**。

你不需要去翻他們的 HTTP API 文件，官方已經把 SDK 封裝得非常完整了。

### 實用範例：用 Python 串 API 撈出歷史 Traces 數據
```python
from langsmith import Client

# 1. 初始化 LangSmith 客戶端 (它會自動去讀取你 .env 裡的 LANGCHAIN_API_KEY)
client = Client()

# 2. 串 API 撈取指定專案的歷史執行紀錄 (Runs)
# 你可以用程式碼精準過濾：只要錯誤的、或者延遲大於 2 秒的
project_runs = client.list_runs(
    project_name="my_crypto_agent",
    error=True, # 只要抓有噴錯的
    limit=5     # 限制最新 5 筆
)

# 3. 留在終端機直接列印數據！
print("--- 正在從 LangSmith API 撈取錯誤紀錄 ---")
for run in project_runs:
    print(f"執行 ID: {run.id}")
    print(f"出錯節點: {run.name}")
    print(f"輸入的 Prompt: {run.inputs}")
    print(f"錯誤訊息: {run.error}")
    print(f"消耗 Token 數: {run.total_tokens}")
    print("-" * 40)
```

## 3. 在 Python 程式執行當下「直接攔截並列印」

如果你的對話前三句說了什麼都覺得處理繁瑣，希望在**跑 LangGraph 的當下，終端機就能直接印出類似 Trace 的樹狀結構**，你可以利用 LangChain 內建的 `ConsoleCallbackHandler`。

你不需要改動 Node 的程式碼，只需要在呼叫 `invoke` 或 `stream` 時，當作 callback 傳進去：
```python
from langchain_core.callbacks import ConsoleCallbackHandler

config = {"configurable": {"thread_id": "trading_001"}}

# 在執行時，傳入 ConsoleCallbackHandler
# 這會讓你的終端機即時詳細列印出每一層 LLM 到底吃了什麼 Prompt、吐了什麼字
app.invoke(
    {"messages": [("user", "分析比特幣阻力位")]}, 
    config=config,
    callbacks=[ConsoleCallbackHandler()] # 關鍵點：即時在終端機詳細列印完整的 Trace 細節
)
```

## 總結你的選擇

- **想看精美的圖表、用 Playground 改 Prompt** $\rightarrow$ 去 **LangSmith 網頁**。
    
- **想在開發當下立刻看清楚模型執行細節** $\rightarrow$ 程式碼內加上 **`ConsoleCallbackHandler()`**，直接在終端機輸出數據。
    
- **想做自動化數據統計、或是將錯誤回報整合到你自己的系統** $\rightarrow$ 使用 `from langsmith import Client` **寫 Python 程式碼直接串 API 撈數據**。
