# ReAct 框架與思考循環

> [!ABSTRACT]
> 深入解析 ReAct 框架的 Thought-Action-Observation 循環、其優化任務拆解的機制，以及如何在 API 無狀態的前提下透過腳手架或 CrewAI/LangChain 實現運行邏輯。

---

ReAct 框架將任務解決過程建模為一個循環迭代鏈，通常被稱為 **TAO 模式 (Thought-Action-Observation)**：

1. **思考 (Thought)**：模型生成口語化的推理軌跡，說明其當前狀態、決策邏輯或識別缺失資訊。
2. **行動 (Action)**：模型根據思考結果，==輸出結構化的工具調用指令（如 JSON 格式）。==
3. **觀察 (Observation)**：外部執行器運行工具並將結果（外部事實）回傳給模型，作為後續推理的新依據。

透過這種模式==(簡單來說就是種Loop，終止條件是當LLM覺得回傳的數值是他要的結果，所以也有可能造成無限迴圈)==，代理人能將內部知識與外部環境獲取的實時資訊相結合，使回應更加可靠且具備事實根據。

---


[[2.Subgoal Management|任務拆解]]是指將複雜的大型目標拆分為多個可管理的**子目標（Subgoals）**。ReAct 透過以下三種方式顯著優化此過程：

1. 動態規劃與更新 (Dynamic Planning)

傳統的「純多步驟推理」容易產生錯誤累積（Error Propagation），一旦初期拆解出錯，後續鏈條就會徹底脫軌。

- **優化機制**：ReAct 允許模型在每個迭代步驟中「誘導、追蹤並更新」行動計畫。模型可以根據觀察步驟獲得的真實數據，**即時修正**原本拆解出的錯誤路徑，或根據新發現的事實動態增加必要的子任務。==允許迴圈反向傳播==

2. 精確定位資訊缺口 (Targeted Information Retrieval)

純行動模式（Action Only）雖然能調用工具，但常因缺乏對總目標的邏輯理解而無法正確整合資訊。

- **優化機制**：ReAct 的「思考軌跡」引導代理人精確定位下一步需要檢索什麼。例如，在處理複合任務時，思考步驟會明確指出：「我需要先找到 A 的年齡，才能進行 B 計算」，這種邏輯引導確保了子任務的拆解具備高度的**目的性**與**準確性**。==將單步驟任務分解成多步驟任務，因此需要能力較強的模型負責規劃==

3. 解決子目標間的非直觀依賴 (Handling Non-obvious Steps)

對於包含許多中間步驟的任務（如研究競爭對手），每個步驟往往依賴於前一步的發現。

- **優化機制**：ReAct 將任務拆解為一系列「思考-行動-觀察」的微小步驟，每一對「思考與行動」都專注於解決一個細分的子目標。這讓模型能專注於當前的資訊處理，避免因一次性規劃過長路徑而導致的邏輯超載或幻覺。==原子化任務內容==


根據研究測試，ReAct 在處理需要精密拆解與外部搜尋的任務中表現優異：

- **HotpotQA（多跳問答）**：ReAct 在結合「自我一致性（Self-Consistency）」後，準確率顯著提升。
- **ALFWorld 與 WebShop（決策型任務）**：在環境決策成功率上，具備良好拆解能力的 ReAct 代理人大幅超越了傳統的強化學習與僅具備行動能力的模式。

總結來說，ReAct 框架不僅是將 [[生成式 AI、LLM 概論|LLM]] 接上工具的手段，更是一種**讓模型學會自我監控與動態調整拆解路徑**的思考作業系統。


雖然現在的模型（如 GPT-4 或 Claude 3.5）在對齊訓練中學會了如何輸出結構化的工具調用（[[Function Calling timing|Function Calling]]），但將這些輸出轉化為一個完整的「思考-行動-觀察」循環，是由外部的程式碼負責的。

1. API 內建的是「工具調用能力」，而非「ReAct 循環」

當你串接 OpenAI 或 Anthropic 的 API 時，API 提供的是一種**數據交換契約**：

- **API 內建功能**：模型被訓練成能識別 JSON Schema，並在你提供的工具目錄中決定該調用哪一個，最後輸出包含參數的 JSON 字串。
- **API 缺乏的部分**：==API 本身是「無狀態」的，它不會主動幫你執行 Python 程式碼、不會自動發起網路請求，也不會自動把工具執行的結果餵回給自己。==

2. 需要「自己設定」或「由框架提供」的部分

要實現 ReAct 框架，你必須建立一個稱為 **Agent Scaffolding（代理人腳手架）** 或 **Agent Executor** 的程式循環

3. 如果不想手動寫循環，該怎麼辦？

- **使用 [[Key Frameworks & Protocols|LangChain]]**：它提供了內建的 `create_react_agent` 函數，你只需要定義好工具和提示詞，它就會自動幫你處理「思考-行動-觀察」的循環。
- **使用 CrewAI 或 AutoGen**：這些框架預設就支持代理人的自主循環，並允許你設置 `max_iterations`（最大迭代次數）來防止模型陷入無限迴圈。

4. 關鍵區分表：內建 vs. 自設

|功能組件|LLM API 內建|需要自己設定/串接框架|
|---|---|---|
|**理解工具功能 (JSON Schema)**|✅|❌|
|**決定調用哪個工具**|✅|❌|
|**執行工具代碼 (如網頁搜尋、計算)**|❌|✅|
|**維護「思考-行動-觀察」循環**|❌|✅|
|**[[3.Reflection and Refinement|自我反思]]與計畫修正**|❌|✅|

**總結建議**：如果你是初學者，建議使用 **LangChain** 或 **CrewAI**。這些框架已經處理了 ReAct 最複雜的「腳手架」部分，你只需要專注於定義工具的 `description`（模型依此判斷何時用它）以及 `parameters`（輸入格式）即可
