# 子目標管理 (Subgoal Management)

> [!ABSTRACT]
> 介紹任務拆解在子目標管理中的角色，並探討其實現機制（如 ReAct 推理與子代理人隔離）以及動態調整與自我修正的效益。

---

在自主代理人系統中，[[生成式 AI、LLM 概論|LLM]] 被視為「大腦」，而規劃則是其核心能力之一。

- **任務拆解（Decomposition）**：代理人將巨大且模糊的任務目標分解為更小、更切實可行的子目標。
- **應對複雜性**：透過一次專注於一個細分環節，子目標管理讓代理人能夠處理那些無法透過單次提示詞完成的高難度項目。


來源提到了幾種不同的方式來引導模型進行子目標的生成與管理：

- **[[1.ReAct|ReAct]] 框架的推理引導**：ReAct 協定利用「思考（Thought）」步驟來引導子目標的生成。模型會明確寫下其推理邏輯，辨識當前缺失的資訊，並決定下一個要達成的子目標（例如：先找出女朋友是誰，再獲取其年齡）。

- **子代理人（[[AI Agent 概論|Subagents]]）的物理隔離**：對於包含非直觀中間步驟或會產生大量噪音的任務，開發者可以將特定的子目標分配給專門的**子代理人**。==只傳送該次任務所需的上下文給subagent==
    - 這種做法能將複雜的中間推理過程封裝在子代理人的獨立上下文視窗中，防止主代理人的決策鏈受到干擾。
    - **減少 Token 浪費**：利用如 **[[MCP Client & MCP Server|MCP]] 的「代碼模式（[[code 模式|Code Mode]]）」**，讓代理人在沙箱內執行複雜邏輯，只回傳最終結果，而非將所有中間數據都餵回模型，這能節省高達 90% 以上的 Token 消耗。


子目標管理並非一次性的靜態計畫，而是一個動態的循環過程(反向傳播)：

- **反思與精煉（[[3.Reflection and Refinement|Reflection & Refinement]]）**：代理人會對過去的行動進行自我批判，分析錯誤並修正後續的子目標路徑。
- **基於觀察的調整**：在「思考-行動-觀察（TAO）」循環中，代理人會根據工具執行的觀察結果（新事實）來更新原本的子目標計畫。如果發現原本的路線行不通，模型會重新規劃下一個子目標。


- **克服物理侷限**：單純的行動模式（Action Only）往往無法正確地將總目標拆解==(不具備反向傳播能力的agent)==，導致在 ALFWorld 等複雜決策測試中失敗率極高。具備良好子目標管理能力的代理人，其成功率顯著提升。
- **資源與效能優化**：透過正確的管理，代理人可以避免無意義的重複嘗試==(避免陷入無限迴圈)==。此外，現代協定如 MCP 的「代碼模式」允許代理人在單一子目標內透過代碼執行複雜邏輯，減少與模型之間來回傳遞 Token 的成本。
- **提升透明度**：結構化的子目標拆解（如 JSON 格式的計畫）讓開發者能更精確地觀測代理人的思考路徑，並在出錯時快速定位問題點。

**總結來說**：LLM 反思的動力來自於它看到了**「自己過去的決策」與「外部真實結果」被並列放在一起**。這種「理想與現實的落差」透過執行器重新灌入上下文視窗，就是讓 LLM 進行自我修正的具體輸入內容
