# 長期記憶 (Long-term Memory)

> [!ABSTRACT]
> 討論長期記憶的技術實現（如向量數據庫與檔案系統之對比）、在記憶系統中的角色、狀態與技能持久化管理，以及其對代理人能力演進的意義。

---

**長期記憶（Long-term Memory）** 被視為讓代理人具備跨越長時間、跨越不同對話任務，進而保留與檢索海量資訊的核心組件。


長期記憶為代理人提供了**保留與召回（無限）資訊**的能力，使其能處理遠超模型預訓練權重限制的知識。

## 一、 - **外部向量數據庫（[[RAG|Vector Store]]）**：
這是長期記憶最普遍的實現方式。代理人透過快速檢索演算法，從外部存儲中提取相關事實，以補足模型預訓練知識的滯後性。
1. ==向量數據庫==（Vector Store / Vector Database）

這是實現長期記憶最普遍且核心的方案。

- **運作方式**：將海量資訊轉化為數值向量，並利用**快速檢索演算法**在推論時提取相關事實。
- **主要功能**：提供代理人跨對話、跨部署地維持並召回資訊的能力，常用於處理遠超預訓練限制的知識。

2. 受管理的==資料庫==與資料倉儲（Managed Databases & Data Warehouses）

透過 **[[MCP Client & MCP Server|MCP]]（模型上下文協定）** 或 API，代理人可以連接到結構化的外部存儲。

- **關聯式資料庫**：如 **Cloud SQL** 或 **Spanner**，允許代理人查詢客戶資訊、庫存或營運數據。
- **資料倉儲**：如 **BigQuery**，用於執行分析任務，從大規模資料集中提取深層見解。

3. ==檔案系統與文件存儲==（Filesystem & Document Stores）

利用檔案存取來維持任務狀態與執行進度。

- **狀態持續性（State Persistence）**：代理人可以將執行的中間結果寫入文件，以便在系統重啟後**恢復工作並追蹤進度**。
- **本地檔案系統**：適合處理私有文件，且具備低延遲與高安全性優點。

4. 持久化技能與知識庫（Persistent Skills & Knowledge Files）

這是一種將「學到的經驗」轉化為長期記憶的高級方案。

- **技能（Skills）**：將成功的程式碼、指令腳本或資源文件儲存為可重用的函數（如 `SKILL.md`）。
- **工具目錄**：透過 MCP 伺服器宣告的資源（Resources），將 FAQ 文件或開發文檔作為唯讀數據提供給代理人。

5. 企業外部系統整合（External Systems Integration）

透過標準化協定（如 MCP）將第三方服務轉化為代理人的外部記憶來源。

- **內容倉庫與工具**：連接如 **Google Drive**、**Salesforce**、**GitHub** 或 **Slack** 等系統，使代理人能存取分散在不同商務軟體中的專業數據
- **跨部署的持續性**：與受限於上下文視窗的[[Short-term Memory|短期記憶]]不同，長期記憶允許代理人**跨對話、跨部署**地維持資訊。這意味著代理人可以「回想起」在過去對話中處理過的類似案例或專業數據。

### **向量數據庫（Vector Store/Database**與**檔案系統（Filesystem)比較

- **向量數據庫（語意檢索）**：
    - **運作方式**：將海量資訊轉化為數值向量（Embeddings），利用**快速檢索演算法**尋找語意相似的內容。
    - **特性**：支持「模糊匹配」。即使使用者問法與存儲內容不完全相同，只要**語意相關**，代理人就能召回相關事實。
    - 涉及嵌入模型的運算，雖然檢索速度快，但==需要維護向量索引==。
    - 適合處理「全量數據中找出關鍵片段」的場景，以減少注入上下文的 Token 消耗。
- **檔案系統（精確存取）**：
    - **運作方式**：透過明確的文件路徑或目錄結構（如 `./servers/`）進行讀取或寫入。
    - **特性**：屬於「精確匹配」。代理人必須知道具體的檔案名稱或透過遍歷目錄來尋找資訊，操作過程如開啟、寫入、刪除是非常**確定且可預測**的。
    - **狀態持續性（State Persistence）**：代理人將**中間執行結果**寫入檔案，這使其能在任務中斷後**恢復工作並追蹤進度**。
    - 適合處理私有文件、本地開發環境數據，或是在沙箱內執行大數據過濾（如處理一萬列的試算表僅回傳結果），進而節省高達 **98.7%** 的 Token 成本。

總結對比表

| 比較維度     | 向量數據庫 (Vector Database) | 檔案系統 (Filesystem)  |
| -------- | ----------------------- | ------------------ |
| **核心功能** | 語意召回、長期記憶知識庫            | 狀態管理、代碼存儲、數據操作     |
| **匹配方式** | 語意相似度 (Embeddings)      | 確定的路徑與名稱           |
| **典型應用** | RAG 檢索、歷史對話召回           | 任務斷點續傳、讀取本地工具、保存技能 |
| **性能優勢** | 處理無限量的非結構化數據            | 極低延遲、高安全性、沙箱內過濾    |



記憶系統通常由短期記憶與長期記憶相輔相成地運作：

- **短期記憶（Context）**：利用模型有限的**上下文視窗（Context Window）**來操縱即時資訊，這被視為在線學習（In-context Learning）的體現。
- **長期記憶（External Storage）**：當任務涉及大量數據、複雜的歷史背景或需要持續累積經驗時，長期記憶就成為**打破物理限制**的關鍵，讓代理人能存取儲存在外部系統中的海量數據。


長期記憶的範疇在現代架構中已擴展到**狀態管理**與**技能累積**：

- **狀態持續性（State Persistence）**：透過檔案系統存取，代理人可以將**中間執行結果**寫入文件，這使其能在中斷後恢復工作並追蹤長期進度。
- **持久化技能（Skills）**：代理人可以將成功的執行程式碼或指令腳本儲存為**可重用的函數（如** **SKILL.md****）**。這種方式將「學習到的經驗」轉化為長期記憶的一部分，供未來遇到相同任務時直接檢索使用。


在代理人複雜度的光譜中，長期記憶是區分「工具調用助手」與「高級自主代理人」的分水嶺：

- **L4 級自主代理人**：被定義為具備 [[1.ReAct|ReAct 循環]]、規劃能力，且擁有**長期記憶**與獨立子任務規劃能力的系統。
- **RAG 與記憶的交集**：檢索增強生成（RAG）常被視為長期記憶的一種應用工具。它將外部權威知識庫作為代理人的記憶來源，在生成回應前檢索相關資訊，以提高事實準確性並減少幻覺。

**總結來說**，長期記憶是代理人系統的**「外掛大腦」**。它不僅解決了模型「知識凍結」的問題，更透過**向量數據庫、狀態持久化與技能存儲**，讓代理人從單次對話的參與者演變成一個具備持續學習與成長能力的**自主解決方案**。
